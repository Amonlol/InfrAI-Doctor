# InfrAI-Doctor

## About

This project is based on opensource [floci:2.5.0](https://github.com/floci-io/floci) and [floci-ui:0.7.0](https://github.com/floci-io/floci-ui) to emulate local cloud sandbox for pre-flight verification on any IaC code. While all codebases are overflowing with AI-generated code, this repo strives into answering question about `"how to stop AI from hitting us in unexpected places"` when working with cloud and automation. Beyond acting as a deployment guardrail, this project serves a second purpose as a benchmarking guidebook to log the limitations of `floci` as a local cloud emulator under the `/docs` section.

## What this project is trying to achieve

InfrAI-Doctor was developed with two core issues in mind:
1. Testing infrastructure in the cloud could be expensive, slow, and inefficient
2. Allowing AI agents to single-handedly orchestrate cloud services can lead to disastrous results

## How it works
1. Creates local floci instance using `docker/init.sh` script
2. Verifies added IaC code by
* **Static tests** (misconfigurations, security, CVE via Trivy/Checkov)
* **Semantic tests** (infrastructure business logic and reachability rules via OPA/Conftest)
* **Emulation test** (API compatibility, idempotency, drift detection via Floci Core)
* **Integration tests** (real functional traffic checks between deployed container apps and emulated AWS databases)
3. On pipeline errors, a specialized diagnostic module securely captures the failure context, then feeds it into LLM (currently supporting Ollama) to show analisys and code patches.
4. Optionally applies the AI-generated patch to a dry-run branch and triggers validation tests again to ensure full remediation.

## 🛡️ Agent Security & Blast Radius Containment
Since this platform acts as an automated sandbox evaluating code generated by untrusted AI agents, security is baked in by design:
* **Prompt Injection Protection:** All raw logs and container output fields are treated as untrusted strings and sanitized to prevent malicious logs from hijacking the evaluator LLM.
* **Data Masking:** Automated pre-flight scanning masks any plain-text string looking like a credential, JWT, or API key before logs leave the pipeline.
* **Strict Isolate Boundary:** The platform enforces strict `localhost` constraints for all execution hooks, guaranteeing that an AI agent cannot drift or accidentally trigger an apply against an actual AWS environment.
* **Fidelity & Policy Layer:** Because local emulators model the Management API layer without true hardware firewalling, the semantic test layer (OPA) runs in parallel to enforce strict cross-resource reachability policies.
